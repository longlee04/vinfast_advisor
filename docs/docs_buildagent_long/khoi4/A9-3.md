# A9-3 — Baseline KPI + judge offline

## 1. Mục tiêu

- Ra báo cáo KPI có số thật và bằng chứng hiệu năng.
- Dựng judge chấm điểm **offline**, nằm ngoài đường chạy thật của sản phẩm.

## 2. Phụ thuộc

- `phan-cong-thanh-vien.md`, mục "Ba điểm ráp chung", ghi: **"Cuối — A9-2 E2E + A9-3 KPI — Long chủ trì, cần cả 4 người xác nhận xong phần mình."**
- Cột "Test bắt buộc" của A9-3 có dòng "**bật/tắt judge không đổi kết quả E2E A9-2**" → **A9-2 phải xong trước A9-3**.
- → Task cuối cùng của cả plan.
- Ghi chú: phần dữ liệu `eval/datasets/kpi_questions.yaml` (bộ câu hỏi) và khung judge có thể soạn sớm vì judge bị cấm import từ `src/agents/` runtime, nhưng **chạy ra số thật** thì phải chờ luồng chạy được.

## 3. Test bắt buộc

Nguyên văn cột "Test bắt buộc" của A9-3, tách mỗi ý một dòng:

- [ ] Báo cáo KPI-1/2/4 có **số thật** trên ≥50 câu
- [ ] p95 ≤6s + 50 phiên đồng thời có bằng chứng
- [ ] **judge không được import từ `src/agents/` runtime** (assert biên một chiều)
- [ ] **bật/tắt judge không đổi kết quả E2E A9-2**

## 4. Bẫy dễ sai

Cột "Bẫy dễ sai" của A9-3 trong `phan-cong-thanh-vien.md` là `—` (không ghi bẫy nào).

## 5. Kế hoạch triển khai

Thứ tự bắt buộc: viết test đỏ → code → test xanh.

1. **Soạn bộ câu hỏi** — `eval/datasets/kpi_questions.yaml` (file thuộc sở hữu Khối 4), tối thiểu 50 câu.
2. **Viết test đỏ trước** cho hai thứ test được bằng code:
   - Test biên một chiều: quét mã trong `eval/` → assert **không** có import nào từ `src/agents/` runtime. Đây là test tĩnh, chạy không cần LLM.
   - Test bật/tắt judge: chạy E2E A9-2 hai lần, một lần bật judge một lần tắt → kết quả E2E giống nhau.
   - Test âm (DoD điều 2): thêm một import vi phạm vào fixture giả → test biên phải đỏ (chứng minh test thật sự bắt được).
3. **Dựng judge offline** trong `eval/` — chấm điểm trên bộ câu hỏi, ghi kết quả vào `eval/results/` (thư mục đã tồn tại, đang có `report.md`).
4. **Đo hiệu năng** — chạy tải để lấy p95 và 50 phiên đồng thời, đính bằng chứng vào `eval/results/`.
5. **Ra báo cáo KPI-1/2/4** với số thật trên ≥50 câu.
6. Chạy lại 3 lệnh của DoD điều 5 tới khi xanh hết.

Ranh giới: judge và mọi thứ trong `eval/` **không** được nằm trên đường chạy thật; `src/agents/` không biết `eval/` tồn tại.

## 6. Checklist Definition of Done

- [ ] Mỗi dòng ở cột "Test bắt buộc" là **một hàm test riêng**, tên test nói rõ điều kiện + kỳ vọng.
- [ ] Có ít nhất **một test âm** (đầu vào sai / biên / rỗng) cho mỗi nhánh code.
- [ ] Test đúng biên: `domain/` và `tools/` chỉ unit test thuần; `services/` dùng fake adapter; chỉ `adapters/` và migration mới được dùng DB thật.
- [ ] Dùng **fake** (class implement đúng port, trả dữ liệu cứng), không dùng `MagicMock()` tự do; spy chỉ dùng cho test đếm.
- [ ] Chạy đủ 3 lệnh, xanh hết:
  ```bash
  uv run pytest tests/agents -q
  uv run ruff check src/agents tests/agents
  uv run mypy src/agents
  ```
- [ ] Chạy lại **toàn bộ** `uv run pytest -q` trước khi push.
