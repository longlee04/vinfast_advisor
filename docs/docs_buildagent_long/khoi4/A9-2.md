# A9-2 — E2E đóng băng

## 1. Mục tiêu

- Chạy hết luồng cho cả hai loại xe trên bộ dữ liệu cố định, kết quả tái lập được.
- Kèm bộ golden sample giọng để người đọc review thủ công.

## 2. Phụ thuộc

- `phan-cong-thanh-vien.md`, mục "Ba điểm ráp chung", ghi: **"Cuối — A9-2 E2E + A9-3 KPI — Long chủ trì, cần cả 4 người xác nhận xong phần mình."**
- → Đây là task **chờ cả 3 khối kia**. Không né được bằng mock: E2E theo định nghĩa là chạy luồng thật.
- Trước A9-2 phải xong "Ráp 3" (Long xoá `INSERT` tay, HITL nhận run thật từ Ngọc).
- Trong Khối 4: cần A9-1 xong trước.

## 3. Test bắt buộc

Nguyên văn cột "Test bắt buộc" của A9-2, tách mỗi ý một dòng:

- [ ] Hai E2E (`CAR` + `ELECTRIC_MOTORBIKE`) xanh
- [ ] **chạy lại cho kết quả giống nhau**
- [ ] golden sample giọng có mẫu để review thủ công

## 4. Bẫy dễ sai

Nguyên văn cột "Bẫy dễ sai":

> Chạy lại 2 lần trong CI để bắt phi tất định, không chạy 1 lần

## 5. Kế hoạch triển khai

Thứ tự bắt buộc: viết test đỏ → code → test xanh.

1. **Dựng seed cố định** — bộ dữ liệu đóng băng dùng chung cho cả hai kịch bản, commit vào repo để ai chạy cũng ra cùng kết quả.
2. **Viết test đỏ** — `tests/agents/integration/test_e2e_frozen.py` (file này đã nằm trong danh sách sở hữu của Khối 4):
   - Hàm 1: E2E nhánh `CAR` xanh.
   - Hàm 2: E2E nhánh `ELECTRIC_MOTORBIKE` xanh.
   - Hàm 3: chạy lại cùng đầu vào → kết quả giống hệt lần trước (so kết quả hai lần chạy, không so với chuỗi viết cứng).
   - Test âm (DoD điều 2): xem mục 7 điểm 4 — chưa rõ test âm ở E2E là gì.
3. **Chạy 2 lần trong CI** đúng theo cột Bẫy dễ sai — cấu hình để bước E2E chạy lặp, không chạy một lần rồi kết luận.
4. **Bộ golden sample giọng** — chuẩn bị mẫu để review thủ công (nơi lưu và số lượng chưa chốt — xem mục 7).
5. Chạy lại 3 lệnh của DoD điều 5 tới khi xanh hết.

## 6. Checklist Definition of Done

- [ ] Mỗi dòng ở cột "Test bắt buộc" là **một hàm test riêng**, tên test nói rõ điều kiện + kỳ vọng.
- [ ] Có ít nhất **một test âm** (đầu vào sai / biên / rỗng) cho mỗi nhánh code.
- [ ] Test đúng biên: `domain/` và `tools/` chỉ unit test thuần; `services/` dùng fake adapter; chỉ `adapters/` và migration mới được dùng DB thật.
- [ ] Dùng **fake** (class implement đúng port, trả dữ liệu cứng), không dùng `MagicMock()` tự do; spy chỉ dùng cho test đếm.
- [ ] Chạy đủ 3 lệnh, xanh hết:
  ```bash
  uv run pytest tests/agents -q
  uv run ruff check src/agents tests/agents
  uv run mypy src/agents
  ```
- [ ] Chạy lại **toàn bộ** `uv run pytest -q` trước khi push.

## 7. Cần chốt trước khi code

| # | Điểm mơ hồ | Câu hỏi cần hỏi lại người giao việc |
|---|---|---|
| 1 | "chạy lại cho kết quả **giống nhau**" — luồng có gọi LLM. LLM không tất định trừ khi bị cố định. | E2E chạy với LLM thật hay LLM giả lập cố định? Nếu LLM thật thì "giống nhau" so ở mức nào — giống từng ký tự, hay chỉ giống các con số và thứ hạng? |
| 2 | "golden sample giọng có mẫu để review thủ công" — không nói bao nhiêu mẫu, lưu ở đâu, định dạng gì, ai review. | Bộ golden sample gồm mấy mẫu, lưu ở đâu (`eval/results/`?), định dạng nào, và ai là người review thủ công? |
| 3 | "Hai E2E xanh" — chưa định nghĩa phạm vi một E2E: bắt đầu từ đâu, kết thúc ở đâu. | E2E chạy từ lượt chat đầu tiên tới bước nào — tới lúc bản nháp vào hàng đợi duyệt, tới lúc tư vấn viên duyệt, hay tới lúc đặt lịch lái thử? |
| 4 | DoD điều 2 đòi test âm cho mọi nhánh, cột "Test bắt buộc" của A9-2 không có test âm nào. | Test âm ở A9-2 là gì — ví dụ luồng gặp guardrail `FAILED` cũng phải tái lập được? |
| 5 | "cần cả 4 người xác nhận xong phần mình" — chưa có tiêu chí xác nhận. | "Xác nhận xong phần mình" là gì: mọi task của khối đó đã merge, hay chỉ cần test khối đó xanh? |
